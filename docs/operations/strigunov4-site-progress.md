# Панель маршрута «Стригунов 4»

Source-only расширение существующей страницы `/dashboard/engine-progress#strigunov4`.
URL после отдельного разрешённого выпуска: тот же origin ASI и этот путь; новый
домен, IP, DNS или отдельная локальная служба не нужны. Публикация PR не означает,
что новая панель уже доступна на действующем сайте.

Страница использует DevelopmentOwnerGuard; GET
`/api/dashboard/engine-progress?view=strigunov4` сначала проверяет существующую
сессию владельца. Старый режим API и панель движка сохранены. Новый режим
не вызывает Mission Control store, БД или серверные операции.

GitHub читается только server-only модулем с уже существующим GITHUB_TOKEN.
Новых secrets/settings нет. Без доступа — неизвестное состояние, а не прошлый
PASS. Ответы private/no-store. Браузер опрашивает каждые 20 секунд при видимой
странице, без перекрывающихся запросов; сервер объединяет параллельные опросы
и хранит снимок не более 20 секунд. Время снимка показывается на странице.

PR #510/#517: полный HEAD, повторная проверка HEAD после чтения, полные bounded
страницы check-runs/statuses, последняя попытка по ID. Required checks берутся
из branch metadata main, неизвестная политика не подменяется догадкой.
CodeRabbit — последний статус от bot ID136622811 на том же SHA; только
success + Review completed означает завершение. Skipped не означает review.
Зелёная карточка не проверяет все условия merge и не является разрешением.

Карта читается из точного main SHA. Пока её там нет (404), отображается проект
карты из текущего HEAD #510 с явной подписью. Ошибки доступа не заменяются
проектом карты. Неполная/переставленная карта и ACCEPTED в кандидате отвергаются.
Принятые этапы main отображаются как заявления карты, не как новая физическая
приёмка. Кривая показывает последовательность шести этапов, не процент,
скорость или оценку оставшихся часов. Число мелких заданий не выдумывается.

Физическое состояние host и менеджера systemd не читается. Напоминание об
условиях ремонта — требование безопасности, не результат новой диагностики.

Проверки: два focused test-файла (server/SSR и owner API), typecheck, touched
ESLint, diff check; обычные CI. Без production/staging, merge и deploy.
После merge #510 этому отдельному UI scope может потребоваться разрешённое
владельцем release exception; эта работа не меняет allowlist карты или защиты.
