# Neighborhood Quality — аудит сигналов (OSM + текущий пайплайн)

> Цель: нейтральные, объективные признаки **физической среды** для слоя «качество среды / риск среды» без демографии и без вывода «плохой район».  
> Источник правды по тому, **что уже качается**: `src/lib/location/overpass.ts` (`buildClauses`, `includeInStrict`), `classifyElement`, плюс производные `gravity-scoring.ts` / `foot-traffic.ts`.

---

## 1. Что уже есть в данных

### 1.1 Строгий запрос (`includeInStrict: true`)

Выполняется всегда (первый проход). В пул попадают в том числе:

| Тип объекта (фильтр Overpass) | После `classifyElement` | Заметка для env-слоя |
|------------------------------|-------------------------|----------------------|
| `aeroway=aerodrome`, `terminal` | `airport` | Прокси авиационной среды (шум/трафик), helipad отфильтрован в классификаторе |
| `railway=station`, `halt` | `railway_station` | Пассажирский/общий ж/д узел, не разделение freight |
| `amenity=bus_station` | `railway_station` | Крупный автобусный хаб |
| `leisure=stadium` | `stadium` | Пиковые события, шум |
| `amenity=cinema/theatre/arts_centre` | `entertainment` | Умеренный сигнал шум/толпа по расписанию |
| `highway=bus_stop`, `stop_position`, часть `platform` / `tram_stop` | `accessibility_stop` | Прокси **линейного транзита** и плотности остановок |
| `landuse=commercial`, офисы, банки | `business` | Для **коммерции** сильный сигнал; для **среды** — в основном шум данных, не «загрязнение» |
| `metro` и прочие магниты | категории магнитов | Для среды: метро скорее accessibility, не «вред» |

### 1.2 Только широкий fallback (`includeInStrict: false`)

Подмешивается, если строгий запрос вернул **< 12 элементов** (или при масштабе радиуса в `buildClauses`), либо в минимальном fallback — **нет**.

Важно для проектирования: **`landuse=industrial`, `man_made=works`, `nightclub`, `bar`, `sports_centre`, часть `platform`** в коде помечены как **не strict**. В плотных городах с «хорошим» strict-набором эти объекты **могут отсутствовать в `elements`**, хотя рядом есть промка или клубы.

**Вывод для MVP:** сигналы, завязанные только на `industrial` / `nightclub` / `bar` из текущего fetch, **нестабильны по покрытию**. Для надёжного env-слоя их нужно либо перевести в strict-селекторы, либо вынести в **отдельный компактный Overpass** «environment strip».

### 1.3 Уже вычисляемая логика (не сырые теги)

- **Расстояния до магнитов**, плотность конкурентов, кластеры — `gravity-scoring.ts` / `buildAnalysis`.
- **Foot traffic** — `foot-traffic.ts`: агрегат по магнитам/остановкам (`movementDensity`, `zoneActivity`, `transitVsTarget` и т.д.) — можно **коррелировать** с «оживлённостью» как прокси пешеходно-транспортной среды, не путать с «преступностью».

### 1.4 Чего в текущем запросе **нет** (центры дорог как ways)

Селекторов вида `way["highway"="motorway"]` в `buildClauses` **нет**: **магистрали, ВПП (`aeroway=runway`), ж/д пути (`railway=rail`), склады (`industrial=warehouse`), подстанции, стройки** в стандартный пул **не попадают**. Их нужно **добавлять отдельными строками запроса** (обычно `way` + `around` + `out center` уже используется в `makeAround(..., allGeometryTypes: true)` для части фильтров).

## 2. Классификация: A / B / C

- **A — можно внедрить сразу:** либо уже стабильно в `elements`, либо **1–3 новых селектора** + простой постпроцесс без внешних API и без этично опасной семантики.
- **B — позже:** внешние или муниципальные данные, калибровка по юрисдикции, SLA/лицензии.
- **C — пока не трогать:** высокий этический/юридический риск, нестабильная интерпретация OSM, или сильная корреляция с социальными стереотипами.

Ниже таблицы: для каждого сигнала — **зачем**, **объяснимость** (для пользователя), **глобальность**, **риск ложных срабатываний (FP)**, **сложность** (низкая / средняя / высокая).

## 3. Группа A — можно внедрить сразу

### A1. Без расширения Overpass (только постобработка `elements`)

| Сигнал | Зачем | Объяснимость | Глобальность | Риск FP | Сложность |
|--------|--------|--------------|--------------|---------|-----------|
| **Близость к `aeroway=aerodrome` (и terminal)** | Авиасреда: шум, ночные вылеты, сервисный транспорт | Высокая: «рядом аэропорт N м» | Высокая | Точка не у ВПП; малые поля; уже частично лечится исключением helipad в `classifyElement` | Низкая |
| **Плотность / близость ж/д узлов** (`railway_station`: station, halt, крупный `bus_station`) | Вибрация, шум поездов, транзитная нагрузка | Средняя: «крупный транспортный узел» не всегда = плохо для жилья | Высокая | Малая станция в деревне; остановка «halt» без интенсива | Низкая |
| **Стадионы / крупные спортплощадки** (`stadium`, именованный `sports_centre` в broad) | Пиковый шум, трафик в дни матчей | Высокая для stadium | Высокая | Стадион далеко за барьером; редкий календарь | Низкая |
| **Плотность остановок ОТ** (`accessibility_stop`) | Прокси **линейного транзита** и «оживлённой» улицы без магистралей в данных | Средняя: нужна формулировка «высокая доступность остановок», не «опасно» | Высокая | В городах с перегруженным автобусом vs город с редкими остановками — разная реальность | Низкая |
| **Состав `business` с `subType` factory / industrial / commercial** | Уже частично отражает завод/промзону/коммерческий landuse **если объект попал в выборку** | Средняя: для `office` путаница с коммерцией | Средняя: в strict без industrial селектора — **пропуски** | `landuse=commercial` как деловой квартал ≠ вред среды | Низкая (код), покрытие — см. A2 |

### A2. С минимальным расширением Overpass (рекомендуется для стабильного MVP)

| Сигнал | Зачем | Объяснимость | Глобальность | Риск FP | Сложность |
|--------|--------|--------------|--------------|---------|-----------|
| **`landuse=industrial` + `man_made=works` + `building=industrial`** (перевести в strict или отдельный мини-запрос) | Промышленная среда, логистика, грубые прокси загрязнения | Высокая | Высокая | Несмапленные промки; офис в бывшей фабрике | Низкая |
| **`amenity=nightclub` + при необходимости `bar`/`pub`** (strict или отдельный запрос) | Ночной акустический фон (не моральная оценка) | Высокая при порогах «N заведений в R м» | Средняя: культура тегирования баров разная | Тихий бар в жилом доме vs туристическая улица | Низкая–средняя |
| **Крупные магистрали** `way["highway"~"motorway|trunk|primary"]` вокруг точки | Heavy traffic adjacency, часть воздушной нагрузки | Высокая: «рядом магистраль» | Высокая | Дублет ways, магистраль в резервуаре/на эстакаде; разные нормы `primary` по странам | Средняя (геометрия ways, центроид) |
| **`aeroway=runway` / `taxiway`** | Точнее, чем один `aerodrome`, для **полосового** шума | Высокая | Высокая | Малые ВПП; военные поля с плохими тегами | Средняя |
| **`railway=rail` + `rail=freight`** (если есть) | Отделить грузовой коридор от пассажирской станции | Средняя | Средняя: `rail=*` заполнен не везде | Пассажирская линия с грузом ночью | Средняя |
| **`landuse=construction`** | Стройка: пыль, шум, грузовики (временно) | Высокая | Средняя | Долго не обновляют тег после стройки | Низкая |

### A3. «Горький коридор» как комбинат (только логика)

| Сигнал | Зачем | Объяснимость | Глобальность | Риск FP | Сложность |
|--------|--------|--------------|--------------|---------|-----------|
| **Stacked burden** (например аэродром + магистраль + industrial в одном кольце) | Сильнее одного фактора; объяснимый композит | Высокая в UI: перечислить факторы | Высокая | Редкое совпадение геометрии | Низкая после наличия базовых слоёв |

## 5. Группа C — пока не трогать

| Сигнал / подход | Почему |
|-----------------|--------|
| **Любые прокси «социального порядка» из OSM** (`amenity=police`, `prison`, избыток `social_facility`, т.п.) | Высокий этический риск и восприятие как «плохой район»; не объективная физика среды. |
| **Плотность `place_of_worship` / этно-религиозные эвристики** | Прямое нарушение нейтральности. |
| **Названия заведений / NLP по `name` для класса людей** | Утечки стереотипов, нестабильно. |
| **Сырые user-generated жалобы без нормализации** | Шум, манипуляции, юридические риски. |
| **`lit=*` как жёсткий сигнал без региональной калибровки** | Культура маппинга не сопоставима между странами → ложные выводы. |
| **Чистый счётчик `tourism=hotel` как «дискомфорт»** | Конкурирует с коммерческой моделью и стигматизирует туризм; для среды — только осторожно в составе **ночной акустики**, не как «много отелей = плохо». |

## 6. Shortlist

### Топ-7 сигналов для MVP

1. **Близость к аэродрому** (`aerodrome` / при добавлении запроса — **к ВПП**).  
2. **Плотность и близость ж/д узлов** (`station` / `halt` / крупный `bus_station`).  
3. **Стадион / крупный event-venue** (`stadium`, при необходимости именованный `sports_centre`).  
4. **Промышленная экспозиция** (`landuse=industrial`, `man_made=works`, `building=industrial`) — **со стабильным попаданием в fetch** (strict или env-мини-запрос).  
5. **Adjacency к магистралям** (`motorway` / `trunk` / `primary` ways) — новый селектор.  
6. **Ночная экономика по порогу** (`nightclub` + опционально `bar`/`pub` в малом радиусе) — **со стабильным fetch**.  
7. **Композит stacked burden** (логика поверх 1–6 + опционально `construction`).

### Топ-5 для второй версии

1. **Шумовые карты или нормативные зоны аэропортов** (официальные слои).  
2. **AQI / NO₂ / PM2.5** (станции или спутник).  
3. **311 / муниципальные обращения** (только где есть открытые API и методология сглаживания bias).  
4. **Freight rail / logistics** (`rail=freight`, склады `industrial=warehouse`, крупные `landuse=commercial` с логистикой — уточнение тегов).  
5. **ДТП или скоростной/инфраструктурный риск** по дорожной сети из официальных открытых наборов.
