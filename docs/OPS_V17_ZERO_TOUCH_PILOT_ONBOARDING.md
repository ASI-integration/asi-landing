# OPS v17: запуск пилота без ручной сборки модулей

OPS v17 добавляет единое сохранённое состояние настройки поверх существующих модулей Booking Ops. Миграция создаёт только новые таблицы, не удаляет и не меняет существующие модули. Она не применялась в рамках разработки.

## Контуры

- `/dashboard/onboarding` — 11-шаговая настройка с сохранением, продолжением и итоговой готовностью.
- `ops-v17/core.ts` — чистые правила прогресса, идемпотентной инициализации, проверки, политик связи и готовности.
- `ops-v17/service.ts` — сохранение, аудит, единичный bootstrap, создание задач по проблемам и активация администратором.
- `ChannelManagerLiveAdapter` — нейтральный контракт импорта, синхронизации, webhook/polling, checkpoint, конфликтов и здоровья. Наличие контракта не означает готовность API конкретного поставщика. Ручной снимок остаётся fallback.
- Главная панель получила добавочный блок исключений; подробный Booking Ops остаётся доступен.

## Безопасность

Сырые пароли не принимаются: сохраняется только ссылка на секрет. Отправка сообщений по умолчанию выключена. Документы, договоры, депозит, МВД, коды доступа, чувствительные инструкции, возвраты, жалобы и конфликтные сообщения требуют проверки. Bootstrap работает только для текущего выбранного аккаунта, сначала показывает dry-run и не отправляет сообщения.
