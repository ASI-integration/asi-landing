# Стригунов 4 — защищённая установка выпуска G0 в staging

**Статус: кандидат исходного кода, не установлен.** Операция не разрешается локальным текстовым отчётом, флагом PASS или запуском ноутбука. Единственный допустимый путь — независимая приёмка PR, объединение в защищённую `main` и отдельный одобренный запуск GitHub Actions в уже защищённом окружении `staging`.

## Что именно проверяет защищённый запуск

- GitHub: только репозиторий ASI-integration/asi-landing, ветка main, точный текущий 40-символьный SHA исходников и workflow, владелец ASI-integration (аккаунт ID 207600140), первая попытка и подтверждение `ACTIVATE_STRIGUNOV4_G0_<SHA>`; секреты SSH/DB доступны только после ручного одобрения владельца в GitHub.
- База: только staging Supabase `meeravcldnmocjtlqoeu`, сертификат `verify-full` и закреплённый PostgreSQL 17 клиент. **Только чтение**, история должна быть `postgres|17|99|7|9`. Если девять миграций ещё не применены — стоп до подключения к серверу.
- Старая служба: `asi-landing-staging`, процесс `asi-runtime`, localhost:3001, прежняя версия `5c91b27bcde395f01cc078d1fbe454dd7436e1c6`, контрольная сумма systemd unit и права env; все **семь настроек запрета отправок** обязаны присутствовать непосредственно в действующем процессе.
- Архив G0: только отдельная уже проверенная карантинная папка владельца сервера; SHA релиза `d912aec6663de90e5ca4293cc5a69e2e0ed9ff94`, дерево `0247b7a5a71b89b8d2c034e6d69340e14dae9ac8`, архив 229060580 байт с SHA256 `030880c750c8fb28cb61ebfbba85e0e23718279e4c165655fcae6a1c2d07c486`.
- Архив сначала копируется во временную закрытую root-папку с повторной проверкой байтов, затем извлекается только с безопасным tar-фильтром в **новую** папку выпуска. Никакие существующие релизы или секреты не заменяются. Проверяются структура пакета, ссылки, исходный SHA и работающий Next.js. Права выпуска назначаются `asi-runtime`.
- После полной подготовки останавливается только `asi-landing-staging`, атомарно меняется символическая ссылка `current` и запускается эта же служба. После запуска обязательно подтверждаются новый SHA, здоровье HTTP, правильный PID и все семь запретов отправок.
- При ошибке запуска — остановка staging, возвращение ссылки на старый выпуск и попытка восстановить старую службу; если проверяемый откат не удался, выдаётся `BLOCK_MANUAL_RECOVERY_REQUIRED`. Старая папка выпуска сохраняется. **Откат приложения НЕ откатывает миграции базы.**
- Конкурирующие запуски SQL и установки используют одну группу GitHub Actions, а на сервере ведётся root-закрытый журнал запусков и блокировка.

## Что не выполняется

Никакие SQL, миграции, команды `db push`, действия с Production/Sentinel, реальные Telegram/WhatsApp/email, OTA и платежи. На время атомарного переключения допустима краткая недоступность только staging. Работающий Production/порт 3000 не затрагивается.

## Приёмка и следующий этап

Ручной запуск возможен только после успешного завершения защищённого SQL-пакета (история 99/7/9), независимого review, успешных Linux тестов и отдельного одобрения GitHub staging. После установки необходим **реальный сквозной синтетический тест** (заявка → оператор/CRM → доступность → бронь → подтверждение/аудит) с нулём внешних отправок и отдельными отрицательными сценариями; одна успешная HTTP-проверка не доказывает полную готовность к демонстрации.

## Защита развёртывания Vercel при изменениях staging

17.10.2026 в проекте `asi-landing-new` через настройки Vercel установлен `Ignored Build Step` со следующей командой:

```sh
git diff --quiet HEAD^ HEAD -- . ':(exclude).github/workflows/strigunov4-*' ':(exclude)docs/strigunov4/' ':(exclude)scripts/strigunov4/'
```

Код завершения `0` пропускает сборку только для служебных изменений по указанным путям. Код `1` или ошибка сравнения оставляет обычную сборку включённой. Любое изменение кода приложения или смешанная правка продолжает выпуск сайта. Проверены отдельные служебные изменения, изменение приложения и смешанный коммит на изолированном Git-стенде; живая проверка через Vercel и защищённый выпуск G0 должны учитываться отдельно.

Это не отключает GitHub Actions, одобрение окружения `staging` или ограничения владельца. Без независимой приёмки и отдельного защищённого одобрения G0 не устанавливать.
