# Стратегия источников госзакупок для раннего радара градостроительства

Цель — получать сигналы по госзакупкам и смежным процедурам для слоя urban development **без зависимости от доступов клиента к ЕИС** и без работы «от имени клиента» в государственных системах.

## Приоритет источников (от предпочтительного к резервному)

1. **Официальные открытые данные ЕИС** — машиночитаемые сведения и открытые выгрузки там, где это разрешено режимом использования и не требует персональных учётных данных клиента отчёта.
2. **Официальный машинный доступ ЕИС / ПМД** — только для собственной серверной инфраструктуры продукта (юридическое лицо / ИП оператора), по отдельным контурам конфигурации; не смешивается с пользовательскими логинами приложения.
3. **Официальные региональные порталы закупок и градостроительства** — там, где регион публикует процедуры и документы в установленном порядке и их можно законно использовать без скрейпинга персональных кабинетов.
4. **Коммерческие API-агрегаторы** — как резерв при наличии договора, аудита качества и юридически выверенного режима данных.
5. **Ручной verified-cache на старте** — курируемые офлайн-выборки и фикстуры для проверки пайплайна и демонстраций; явно помечаются как не «живой» контур.
6. **HTML-скрейпинг закрытых или нестабильных страниц** — **запрещённый / крайний вариант**: допускается только если иным способом нельзя получить те же сведения, есть явное юридическое заключение и контроль частоты/объёма; по умолчанию не используется.

## Что мы **не** делаем

- Не просим клиентов вводить логины, пароли или токены ЕИС для построения отчёта по адресу.
- Не храним электронные подписи и ключи ЭП пользователей.
- Не выполняем действия в ЕИС от имени клиента (ни подачей заявок, ни «работой под их УКЭП»).
- В пользовательском контуре отчёта клиент задаёт **адрес объекта** и **контакт для отчёта** (например e-mail или мессенджер), а не учётные данные госсистем.

## Privacy guardrails

- **Минимизация ПДн**: собираем только то, что нужно для расчёта отчёта и доставки результата.
- **Не храним** паспортные данные и иные избыточные идентификаторы физлица сверх необходимости.
- **Не храним** доступы к Госуслугам, ЕИС и прочим государственным кабинетам пользователя.
- **Адрес объекта** используется как вход гео/городского слоя для расчёта отчёта; не смешивается с техническими raw-сигналами без необходимости.
- **Контактные каналы** (e-mail, Telegram и т.д.) хранятся и обрабатываются **отдельно** от сырых технических сигналов закупок (отдельные модели данных и политики TTL/удаления).

## Связь с кодом live probe

Тип `PublicProcurementSourceAccessMode` в слое `public-procurement` фиксирует заявленный режим доступа к источнику для раскрытий и внутренних проверок:

| Значение          | Смысл |
|-------------------|--------|
| `open_data`       | Открытые официальные данные без интерактивной авторизации клиента. |
| `official_api`    | Официальный машинный доступ (контур оператора продукта). |
| `commercial_api`  | Коммерческий агрегатор по договору. |
| `verified_cache`  | Проверенный офлайн кеш / фикстуры (по умолчанию для sample-cache при выключенном live-флаге). |
| `disabled`        | Живой контур выключен или намеренно не отдаёт данные (например, включён флаг probe без подключённого upstream). |

Этот документ — стратегический ориентир; конкретные коннекторы и режимы включаются отдельными задачами и конфигурацией окружения.
