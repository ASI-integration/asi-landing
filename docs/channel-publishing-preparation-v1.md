# Channel Publishing Preparation v1

## Назначение

Слой готовит безопасный пакет карточки объекта для выбранного менеджера каналов и выбранных площадок. Он не публикует карточки во внешних OTA, не вызывает внешние API и не включает автоматическую синхронизацию.

Честный пользовательский статус: «Готово к ручной/пилотной публикации через выбранный менеджер каналов». Статус `published_placeholder` означает только ручное подтверждение оператора и не доказывает работу OTA API.

## Аудит исходного контура

| Область | Классификация до v1 | Что уже было |
| --- | --- | --- |
| Профиль настройки объекта | Автоматически | Название, безопасное расположение, тип, комнаты, вместимость, время заезда/выезда, статусы правил, фото, цены и доступа |
| Готовность объекта | Автоматически | `readiness_score`, `missing_fields`, переход к подготовке менеджера каналов |
| Фото и assets | Полуавтоматически | Безопасные storage refs и подписи; приём и проверка остаются у оператора |
| Описание и правила | Полуавтоматически | Текст берётся только из разрешённых полей; короткое описание может быть собрано из типа, расположения и вместимости |
| Базовая цена | Полуавтоматически | Статус цены существовал, но для публикации дополнительно требуется безопасная текстовая сводка `base_price_label` |
| Выбор площадок | Ручной | Владелец или администратор выбирает каналы, включая действие «Выбрать все поддерживаемые» |
| Provider onboarding | Полуавтоматически | Bnovo, RealtyCalendar, TravelLine и ручной snapshot; статусы доступа и подготовки фиксируются без сырых credentials |
| Snapshot import и reconciliation | Полуавтоматически | Объекты, брони, календарь и цены можно импортировать и сверить внутри ASI |
| Реальная OTA-публикация | Заблокировано | Внешний адаптер, партнёрские доступы и явное разрешение outbound отсутствуют; API sync выключен |
| Подтверждение публикации на площадке | Ручной | Оператор может поставить только явно обозначенный ручной placeholder-статус |

## Что добавлено

- `booking_channel_publication_packages` — пакет, score, недостающие поля, предупреждения и allowlist payload.
- `booking_channel_publication_channels` — выбранные площадки и честный статус по каждой площадке.
- `booking_channel_publication_checks` — результаты обязательных проверок.
- Service layer `channel-publishing-preparation.ts` для создания, сборки, проверки, выбора каналов и контролируемых переходов статуса.
- Защищённые dashboard API для списка, статуса и действий.
- Компактная панель «Публикация в каналах» на `/dashboard/property-knowledge` и `/dashboard/booking-ops`.
- Черновые коммуникационные intents через существующую политику Communication Orchestrator; глобальная автоотправка не включается.

## Проверки готовности

Пакет считается готовым только когда:

1. заполнено название;
2. есть безопасная сводка расположения;
3. указан тип объекта;
4. указана вместимость;
5. достаточно фото (минимум три безопасных assets либо подтверждённый статус `enough`/`ready`);
6. есть описание или достаточно безопасных полей для его генерации;
7. правила имеют статус `complete`;
8. заполнено время заезда и выезда;
9. цена имеет статус `ready` и заполнен `base_price_label`;
10. выбран хотя бы один канал;
11. выбраны провайдер и connection;
12. доступ имеет допустимый подготовительный статус: `received`, `access_received`, `import_ready`, `pilot_activation_pending` или `connected_placeholder`;
13. allowlist payload не содержит закрытых данных.

Score — доля успешно пройденных проверок. `ready_for_publication` не означает, что объект уже опубликован.

## Безопасный payload

Включает только разрешённые данные: название, безопасное описание расположения, тип, вместимость, число комнат, удобства, безопасное описание и правила, время заезда/выезда, несекретное описание заселения, storage refs/подписи фото, сводку цены, список выбранных каналов, provider key и результаты readiness checks.

Не включает:

- пароль Wi‑Fi;
- код двери, домофона или lockbox;
- пароль, токен, API key или иные credentials менеджера каналов;
- паспортные и иные документы;
- данные гостя;
- платёжные секреты;
- полные закрытые инструкции по доступу.

Вложенные action payloads и metadata проходят ту же проверку. При обнаружении закрытого ключа или похожего значения запрос отклоняется.

## Статусы и ручной процесс

`draft` → `incomplete` или `ready_for_review` → `ready_for_publication` → `publication_pending` → `published_placeholder`.

- `ready_for_review` — данные собраны, требуется проверка.
- `ready_for_publication` — можно начинать ручную или пилотную публикацию через выбранный менеджер каналов.
- `publication_pending` — публикация ожидает активации провайдера или ручного подтверждения.
- `published_placeholder` — оператор вручную подтвердил результат; автоматическая OTA-синхронизация по-прежнему не заявляется.
- `blocked` — дальнейшие действия остановлены с безопасной причиной.

## Коммуникации

Поддерживаются intents:

- `publication_package_ready_notice`;
- `publication_missing_data_request`;
- `channel_selection_needed_notice`;
- `publication_pending_notice`;
- `internal_status_notice`.

Они сохраняются как `draft_ready`, проходят действующую auto-send policy и не включают закрытые данные. Этот слой не отправляет реальные сообщения сам и не меняет глобальный режим автоотправки.

## Что остаётся ручным или заблокированным

- создание/настройка аккаунта у провайдера;
- партнёрская активация и передача доступа согласованным безопасным способом;
- проверка карточки оператором;
- фактическая публикация и подтверждение результата на площадках;
- разбор требований конкретной площадки, которых нет в общей карточке;
- включение реального provider/OTA API adapter и outbound — отдельная задача с отдельным разрешением.
