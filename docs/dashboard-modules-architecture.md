# Архитектура модулей личного кабинета ASI

_Обновлено: 2026-05-24. Стратегия: Россия в приоритете; OTA (Airbnb / Booking) не задают форму слоя подключений._

## Контекст продукта

- **Основной продукт** — операционная платформа для посуточной аренды: коммуникация, операции, данные о бронированиях и занятости.
- **Подключения каналов** — вход данных из российских менеджеров каналов и PMS (RealtyCalendar, Bnovo, TravelLine, ручной импорт), а не проектирование вокруг глобальных OTA.
- **Аналитика локации** — модуль в кабинете / по подписке; **не** главная публичная воронка продаж. Отдельный платный публичный location-report выведен из активного фокуса.
- **Distribution runtime** (`src/lib/distribution`, `dist_*`) — отдельный контур исходящей дистрибуции на OTA; не смешивать с подключением менеджера каналов как источника правды по броням.

## Четыре модуля кабинета

| Модуль | Назначение | Источник правды | Зрелость (ориентир) |
|--------|------------|-----------------|---------------------|
| **Коммуникация** | Диалоги с гостями и операторами (Telegram, VK, email, телефон и др.) | События каналов + контекст брони/объекта | Пилот, много тестов в `src/lib/communication` |
| **Операции** | Этапы проживания, чек-листы, эскалации, задачи на смену | Брони и объекты из подключённого источника + коммуникация | Пилот, `src/lib/operations`, `src/lib/ops` |
| **Подключения каналов** | Импорт объектов, броней, дат, цен и занятости из менеджера каналов | Внешний менеджер каналов / PMS (RU-first) | Фундамент типов и UI; API провайдеров — позже |
| **Аналитика локации** | Скоринг и отчёты по адресу для решений о доходности | Движок `src/lib/location` + entitlements | Движок зрелый; продажи — через кабинет, не standalone-воронка |

## Поток данных (упрощённо)

```
Менеджер каналов (RU) ──► Подключения каналов ──► Объекты / брони / календарь
                              │
                              ├──► Операции (этапы, чек-листы)
                              │
                              └──► Коммуникация (контекст гостя и брони)

Аналитика локации ◄── адрес / объект (по запросу, подписка)
     (не блокирует операционный контур)
```

## Подключения каналов

**Задача:** дать ASI единый нейтральный слой статусов и сущностей до появления реальных интеграций.

- Провайдеры: RealtyCalendar, Bnovo, TravelLine, ручной импорт, задел под будущего провайдера.
- Сущности: провайдер, статус подключения, статус синхронизации, связанный объект, статус импорта броней, время последней синхронизации, текст ошибки синхронизации.
- Код: `src/lib/channel-connections/*`, UI: `/dashboard/channel-connections`.
- Credentials и вызовы внешних API — вне текущего scope.

## Коммуникация

- Входящие/исходящие сообщения, сценарии, эскалация к оператору.
- Зависит от идентификации гостя и привязки к брони (после подключения каналов).
- Не путать с «каналом» в смысле OTA: в коде communication `channel` = мессенджер/email.

## Операции

- Workflow по этапам проживания, чек-листы, issues, связь с OPS-контуром (`src/lib/ops`).
- Требует актуальных броней и объектов из подключений каналов или ручного ввода.

## Аналитика локации

- Доступна в кабинете (`/dashboard/reports` и связанные entitlements).
- Публичный быстрый демо-слой локации может оставаться на лендинге; **полный отчёт и PDF** — не центр текущей GTM-стратегии.
- Изменения скоринга и SSOT — только по отдельным задачам (см. AGENTS.md).

## Следующие шаги (инкрементально)

1. Подключения каналов: persistence, OAuth/API по провайдерам, фоновый sync.
2. Связка импортированных броней с коммуникацией и операциями.
3. Аналитика локации: упаковка под подписку в кабинете без усиления standalone-воронки.
